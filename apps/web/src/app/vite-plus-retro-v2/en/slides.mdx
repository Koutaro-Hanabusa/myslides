What Is Vite+?

</PersonalHeadingSlide>

<PersonalContentSlide title="What Is Vite+?">

- A unified toolchain that brings test / lint / fmt / task and more under one `vp` command
- Built on Vite / Vitest / Oxlint / Oxfmt / tsdown / Vite Task, all by VoidZero
- Released on March 13, 2026, and still in alpha

</PersonalContentSlide>

<PersonalContentSlide title="The Problem Vite+ Solves">

- Other languages commonly have unified toolchains
- JavaScript offers many tools, so every environment tends to use a different setup
- → Vite+ solves this fragmentation

</PersonalContentSlide>

<PersonalContentSlide title="Configuration Gets Scattered">

<CodeBlock lang="text" code={BEFORE_AFTER_CONFIG} />

- test / lint / fmt / build / task / hooks often use separate tools and config files
- Vite+ can consolidate them in `vite.config.ts`

</PersonalContentSlide>

<PersonalHeadingSlide>

How Did It Go?

</PersonalHeadingSlide>

<PersonalContentSlide title="Win 1: vp migrate Is Excellent">

- A starting point for migrating an existing project to Vite+
- Updates dependencies, imports, config files, and scripts together
- Also sets up hooks, AI agents, and editor settings

</PersonalContentSlide>

<PersonalContentSlide title="Win 2: Configuration in One Place">

<CodeBlock lang="ts" code={ALL_IN_ONE_CONFIG} />

- All configuration lives together in `defineConfig` inside `vite.config.ts`
- test / staged / fmt / run / lint fit in one file
- `vp lint` even runs type-aware linting with oxlint-tsgolint

</PersonalContentSlide>

<PersonalContentSlide title="Win 3: Caching Makes It Blazing Fast">

<CodeBlock lang="text" code={VP_TASK_CACHE_LOG} />

- Automatically tracks files used by a task; if nothing changes, it replays the result without running it
- In our measurement: 4/5 cache hits and 27.38 seconds saved
- This article explains it very well:
  - https://zenn.dev/herp_inc/articles/strange-task-runner

</PersonalContentSlide>

<PersonalContentSlide title="Win 4: Library Mode = vp pack">

<div className="grid grid-cols-2 gap-4">
  <CodeBlock lang="ts" code={LIBRARY_MODE_CONFIG} />
  <CodeBlock lang="text" code={PACK_SIZE_DIFF} />
</div>

- One line, `dts: true`, generates declarations without `vite-plugin-dts`; React packages are treated as external
- Moving from Rollup to tsdown cut gzipped ESM from 117KB to 36KB, about one third

</PersonalContentSlide>

<PersonalContentSlide title="Win 5: No Separate Tools Needed">

<CodeBlock lang="ts" code={STAGED_HOOKS_CONFIG} />

- Git hooks come with `vp`; add `staged` and you do not need husky or lefthook
- Custom pre-commit logic can live in `.vite-hooks/`
- Node only needs `.node-version`; for our use case, mise or Volta was unnecessary

</PersonalContentSlide>

<PersonalHeadingSlide>

Of Course, We Hit Some Pain Points

</PersonalHeadingSlide>

<PersonalContentSlide title="Pain 1: lefthook Was Not Migrated">

- During `vp migrate`, lefthook was not migrated automatically; we only got a warning
- We missed it and our pre-commit hook broke, so we fixed the config manually

</PersonalContentSlide>

<PersonalContentSlide title="Then We Learned It Was Intentional">

- We thought it was a bug and opened [issue #1854](https://github.com/voidzero-dev/vite-plus/issues/1854)
- On closer reading, it was documented behavior in the RFC
- → The team addressed it by updating the Migration Guide in [PR #1901](https://github.com/voidzero-dev/vite-plus/pull/1901), which is now merged

</PersonalContentSlide>

<PersonalContentSlide title="Pain 2: The Astro Build Broke">

- Astro 6 expects Vite 7, but `overrides.vite` replaced it with the Vite 8 version bundled by Vite+
- Compatibility code for an esbuild API used by dev-toolbar threw `Not implemented`, breaking the build
- Removing the override restored Astro's Vite 7 and fixed the build
- We later upgraded to the Astro 7 beta, which uses Vite 8, and `core@0.1.24`

</PersonalContentSlide>
