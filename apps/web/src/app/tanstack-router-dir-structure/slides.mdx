<PersonalHeadingSlide>

第 1 部
TanStack Router

</PersonalHeadingSlide>

<PersonalHeadingSlide>

そもそも、なぜ TanStack？

</PersonalHeadingSlide>

<PersonalContentSlide title="技術選定">

- 社内で 0 から作り直す大規模なリプレイス中、フロントの技術選定を行った
- 候補は **Next / React Router / TanStack Router** の三案

</PersonalContentSlide>

<PersonalContentSlide title="三案の比較">

- **Next** … ロックインの辛さ、キャッシュコンポーネント等の難しい概念
- **React Router** … 現状使用中。でも新しく作るなら新し目を選びたい
- **TanStack** … 辛くなく、モダン寄りって感覚

→ **TanStack Router を採用**

</PersonalContentSlide>

<PersonalHeadingSlide>

TanStack Routerの良さって？

</PersonalHeadingSlide>

<PersonalContentSlide title="TanStack Routerの良さ">

- 型安全なルーティング
- URL での状態管理
- ファイルベースルーティング
- `-` での routes 配下の子ロケーション

</PersonalContentSlide>

<PersonalContentSlide title="でも、意外と大変だった">

- 実際の事例が少なく、採用してみると躓いた
- PoC を進めつつ、**どうすれば TanStack の良さを活かせるか**を考えた

</PersonalContentSlide>

<PersonalHeadingSlide>

構成、どうする？

</PersonalHeadingSlide>

<PersonalContentSlide title="三案を考えた">

1. **features に寄せる**
   一般的な形。bulletproof react などでも出てくる
2. **routes に全部押し込む**
   `-` でコロケーションできるので全部詰める
3. **ハイブリッド**
   TanStack の影響を受ける部分は routes、ロジックの実態は features

</PersonalContentSlide>

<PersonalContentSlide title="ハイブリッドを採用">

- 機能を活かしつつ、変更も容易にしたい
- → 結果的に **三つ目（ハイブリッド）** を採用

</PersonalContentSlide>

<PersonalHeadingSlide>

こんな感じにしました！

</PersonalHeadingSlide>

<PersonalContentSlide title="ディレクトリ構成">

```text
apps/<appname>/src/
├── features/
│   └── <domain>/
│       ├── api/        ← queryOptions / mutationOptions / API I/O
│       ├── hooks/      ← useSuspenseQuery / useMutation を呼ぶ hook
│       ├── components/ ← View 断片（Router 非依存）
│       └── types.ts    ← ドメイン型・route と共有する Enum
└── routes/
    └── <route>/
        ├── -components/
        │   ├── fallbacks/  ← 必要なルートのみ（pending / error の中身）
        │   └── Page.tsx    ← Page 本体（Router 依存を features に注入）
        └── index.tsx       ← validateSearch / loader / アダプタの宣言のみ
```

</PersonalContentSlide>

<PersonalContentSlide title="ディレクトリ構成（+ server）">

```text
apps/<appname>/src/
├── features/
│   └── <domain>/
│       ├── api/        ← queryOptions / mutationOptions / use-<verb>-<entity>
│       ├── server/     ← ★ Server Function
│       │   ├── <entity>.functions.ts  ← createServerFn のラッパー
│       │   ├── <entity>-schema.ts     ← 入出力の schema
│       │   └── <verb>-<entity>.server.ts ← ロジック
│       ├── hooks/      ← useSuspenseQuery / useMutation を呼ぶ hook
│       ├── components/ ← View 断片（Router 非依存）
│       └── types.ts    ← ドメイン型・route と共有する Enum
└── routes/
    └── <route>/
        ├── -components/ ← fallbacks / Page.tsx
        └── index.tsx    ← validateSearch / loader / アダプタの宣言のみ
```

</PersonalContentSlide>
